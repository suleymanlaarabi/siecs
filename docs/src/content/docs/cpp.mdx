---
title: C++ API
description: Type-safe C++23 wrapper around the SIECS C runtime.
---

The C++ API is a thin C++23 wrapper around the SIECS C runtime. Include the
single public header:

```cpp
#include <siecs.h>
```

## World Lifecycle

The wrapper exposes the runtime lifecycle through the `ecs` namespace:

```cpp
ecs::init();

// Create entities, queries, systems, and observers here.
ecs::progress();

ecs::fini();
```

## Entities And Components

Components are ordinary C++ types. Registering them is lazy: the first typed
operation registers the component in the active world.

```cpp
struct Position {
    float x, y;
};

struct Velocity {
    float x, y;
};

auto entity = ecs::entity::create("player");
entity.set(
    Position{ .x = 0.0f, .y = 0.0f },
    Velocity{ .x = 1.0f, .y = 0.0f }
);

if (entity.has<Position, Velocity>()) {
    entity.remove<Position, Velocity>();
}

entity.kill();
```

Use `entity.add<A, B>()` for tags or zero-initialized components. Operations
with several components are combined into one deferred mutation, so the entity
moves directly to its final archetype. Use `entity.get<T>()` and
`entity.try_get<T>()` for direct typed access, and `entity.child_of(parent)` for
the built-in `ChildOf` relation.

## Queries

Query terms are inferred from callback parameters. Mutable references are
writable terms; `const` references are read-only terms.

```cpp
struct Velocity {
    float x, y;
};

ecs::query()
    .require<Position>()
    .exclude<ecs::Disabled>()
    .each([](Position &position, const Velocity &velocity) {
        position.x += velocity.x;
        position.y += velocity.y;
    });
```

Use `.require<T>()` for filter-only terms and `.first()` when only one matching
entity is needed.

## Systems

Systems use the same callback inference and run when the world progresses:

```cpp
ecs::system("Move")
    .phase(EcsOnUpdate)
    .each([](Position &position, const Velocity &velocity) {
        position.x += velocity.x;
        position.y += velocity.y;
    });

ecs::progress();
```

## Resources

Resources are typed values stored once per world. A resource callback parameter
does not become a query term.

```cpp
struct Time {
    float dt;
};

ecs::set_resource(Time{ .dt = 0.016f });

ecs::query().each([](ecs::res<const Time> time, Position &position) {
    position.x += time->dt;
});
```

The resource can also be accessed directly with `ecs::resource<T>()` or tested
with `ecs::has_resource<T>()`.

## Observers

Register an observer for a built-in event with a typed callback:

```cpp
ecs::observe<ecs::OnSet>().each([](const Position &position) {
    (void)position;
});
```

The wrapper also exposes `ecs::OnAdd`, `ecs::OnRemove`, and custom event types.

## Relations And Inheritance

Use the typed entity helpers for the built-in relation and inheritance APIs:

```cpp
auto parent = ecs::entity::create();
auto child = ecs::entity::create().child_of(parent);

auto prototype = ecs::entity::create().abstract();
auto instance = ecs::entity::create().is_a(prototype);
```

Inherited component data is shared from the base until the instance sets its own
value, matching the C runtime semantics described in the inheritance guide.
