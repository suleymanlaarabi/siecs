---
title: Modules
description: Group components, systems, and observers into reusable modules with idempotent imports and predictable costs.
---
import { Tabs, TabItem } from '@astrojs/starlight/components';

Modules are import units. They let a library or feature register its components,
relations, systems, and observers through one entry point.

Entities are not attached to modules. Component data is not removed when a
module is disabled.

## Declare a Module

Declare a C-compatible module in a shared header:

<Tabs syncKey="language">
<TabItem label="C">
```c
ECS_MODULE_DECLARE(physics, {
    float gravity;
});
```
</TabItem>
<TabItem label="C++">
```cpp
// The declaration also exposes a typed C++ adapter named `physics`.
#include "physics.h"

auto physics = ecs::import<physics>(physics::props_t{ .gravity = 9.81f });
```
</TabItem>
</Tabs>

This creates typed module properties named `physics_props_t` and declares the import
function. When included from C++, the declaration also exposes an adapter type
named `physics` with `physics::props_t`.

<Tabs syncKey="language">
<TabItem label="C">
```c
void physics_import(const physics_props_t *props);
```
</TabItem>
<TabItem label="C++">
```cpp
// Generated by ECS_MODULE_DECLARE(physics, ...):
// - the `physics` adapter type
// - `physics::props_t`
// - the shared module id and import callback
```
</TabItem>
</Tabs>

## Define and Import

Define the module in exactly one C file:

<Tabs syncKey="language">
<TabItem label="C">
```c
ECS_MODULE_DEFINE(physics);

void physics_import(const physics_props_t *props) {
    ECS_COMPONENT_REGISTER(Position);
    ECS_COMPONENT_REGISTER(Velocity);

    ecs_system({
        .name = "Move",
        .phase = EcsOnUpdate,
        .query = {
            .terms = { ecs_inout(Position), ecs_in(Velocity) },
        },
        .callback = move_system,
    });

}
```
</TabItem>
<TabItem label="C++">
```cpp
// No second definition is required. The C declaration and implementation
// above are also the C++ module implementation.
```
</TabItem>
</Tabs>

Import it from application code:

<Tabs syncKey="language">
<TabItem label="C">
```c
ecs_module_id_t Physics = ECS_MODULE_IMPORT(physics, {
    .gravity = 9.81f,
});
```
</TabItem>
<TabItem label="C++">
```cpp
auto physics = ecs::import<physics>(physics::props_t{ .gravity = 9.81f });
```
</TabItem>
</Tabs>

The props are passed only to `physics_import()`. Store any runtime settings
you need in components, globals owned by your module, or user-managed state.

## Empty Modules

Modules with no parameters still use empty props:

<Tabs syncKey="language">
<TabItem label="C">
```c
ECS_MODULE_DECLARE(rendering, {});
ECS_MODULE_DEFINE(rendering);

void rendering_import(const rendering_props_t *props) {
    /* Register rendering systems and observers. */
}

ECS_MODULE_IMPORT(rendering, {});
```
</TabItem>
<TabItem label="C++">
```cpp
struct Rendering {
    static void import() {
        ecs::system("Render").each([](Position &position) {
            position.x += 0.0f;
        });
    }
};

auto rendering = ecs::import<Rendering>();
```
</TabItem>
</Tabs>

## What Gets Captured

During `ECS_MODULE_IMPORT()`, SIECS records registrations made through the
normal public API:

<Tabs syncKey="language">
<TabItem label="C">
```c
ECS_COMPONENT_REGISTER(Position);
ecs_system({ /* ... */ });
ecs_observer({ /* ... */ });
```
</TabItem>
<TabItem label="C++">
```cpp
struct Physics {
    static void import() {
        ecs::system("Move").each([](Position &, const Velocity &) {});
        ecs::observe<ecs::OnSet>().each([](const Position &) {});
    }
};
```
</TabItem>
</Tabs>

Those ids are appended to the active module. User code does not need a separate
`module_add_*` call.

Nested imports are supported. If one module imports another, registrations made
after the nested import continue to belong to the parent module.

## Enable and Disable

Modules are enabled by default. Disabling a module disables only the systems and
observers recorded by that module:

<Tabs syncKey="language">
<TabItem label="C">
```c
ecs_module_disable(Physics);
ecs_module_enable(Physics);
```
</TabItem>
<TabItem label="C++">
```cpp
physics.disable();
physics.enable();
```
</TabItem>
</Tabs>

Components and relations stay registered. Existing component data stays valid.
Component hooks still run because hooks belong to components, not to the module
scheduler.

Import a module disabled with the generic API:

<Tabs syncKey="language">
<TabItem label="C">
```c
physics_props_t props = { .gravity = 9.81f };

ecs_module_id_t Physics = ecs_module({
    .name = "physics",
    .id = &ecs_id(physics),
    .import = ecs_id(physics_import_wrapper),
    .desc = &props,
    .desc_size = sizeof(props),
    .disabled = true,
});
```
</TabItem>
<TabItem label="C++">
```cpp
auto physics = ecs::import<Physics>(9.81f);
physics.disable();
```
</TabItem>
</Tabs>

## Idempotency

Imports are idempotent for the active world. Importing the same module twice
returns the same module id and does not register duplicate systems or observers:

<Tabs syncKey="language">
<TabItem label="C">
```c
ecs_module_id_t first = ECS_MODULE_IMPORT(physics, { .gravity = 9.81f });
ecs_module_id_t second = ECS_MODULE_IMPORT(physics, { .gravity = 1.0f });

/* first == second */
```
</TabItem>
<TabItem label="C++">
```cpp
#include <cassert>

auto first = ecs::import<Physics>(9.81f);
auto second = ecs::import<Physics>(1.0f);

assert(first.id() == second.id());
```
</TabItem>
</Tabs>

The first props value wins. Later imports with different props values do not
reconfigure an already imported module.

SIECS stores the imported id in the generated `ecs_id(module_name)` symbol and
resets it during `ecs_fini()`. A later world can import the module again, but the
same typed module is not supported in two live worlds at the same time.

## Performance Model

Modules do not add checks to query iteration, table matching, or system
callbacks. Capture happens only during registration.

Enable and disable are linear over the ids stored in the module:

- systems are toggled with `ecs_system_enable()` and `ecs_system_disable()`
- observers are toggled with `ecs_observer_enable()` and `ecs_observer_disable()`
- components are retained for ownership/debug information and are not toggled

The runtime handle is `ecs_module_id_t`; no string lookup is needed to enable or
disable a module.
