Include the public API with:

```c
#include <siecs.h>
```

See [API stability and documentation policy](/reference/stability/) for
preconditions, edge-case conventions, experimental APIs, and the compatibility
policy applied to every declaration.

## C++ wrapper

The typed wrapper is included by `siecs/cpp.hpp` (or automatically by
`siecs.h` in C++ builds). Its public types
are `ecs::entity`, `ecs::query`, `ecs::query_handle`, `ecs::system`,
`ecs::observer<T>`, `ecs::observer_event`, `ecs::module_ref<T>`,
`ecs::resource_ref<T>`, `ecs::resource_hooks<T>`, and
`ecs::component_hooks<T>`. Free functions in `ecs` mirror world lifecycle
(`init`, `fini`, `quit`, `progress`, `run`, `run_phase`), registration
(`component`, `relation`, `component_requires`), resources
(`set_resource`, `resource`, `try_resource`, `has_resource`,
`remove_resource`), modules (`import`, `module`), observers (`observe`,
`event`, `trigger`), and systems (`run_system`, `enable_system`,
`disable_system`).

All typed handles are non-owning values: the world must be initialized, and a
handle must not be used after `fini` or entity destruction. `entity::get` and
`resource` require the value to exist; use `try_get`/`try_resource` when
absence is valid. `entity::set` and `set_resource` copy lvalues and move
rvalues, invoking the registered C++ lifecycle operations. Callback arguments
are valid only for the callback invocation. Template constraints and
overloads are documented in the corresponding public header; `detail::`
names are implementation details and are not part of the API.

## Core Types

| Type | Meaning |
| --- | --- |
| `ecs_entity_t` | Entity handle. |
| `ecs_component_t` | Component id. |
| `ecs_query_id_t` | Query id. |
| `ecs_system_id_t` | System id. Id `0` is reserved. |
| `ecs_event_t` | Observer event id. |
| `ecs_module_id_t` | Module id. Id `0` is reserved. |
| `ecs_resource_t` | Resource id in the separate resource id space. |
| `ecs_observer_id_t` | Observer id. |
| `ecs_table_t` | Opaque archetype table passed to query order callbacks. |
| `ecs_iter_t` | Query iterator. Users may read `count`. |

## World

```c
void ecs_init(void);
void ecs_init_w_features(const ecs_world_feat_desc_t *features);
bool ecs_progress(void);
void ecs_run(void);
void ecs_quit(void);
void ecs_fini(void);
```

```c
typedef struct {
    uint16_t target_fps;
} ecs_world_feat_desc_t;

#define ecs_with_features(...)
```

`target_fps` caps `ecs_progress()` by sleeping for the remaining frame time when
non-zero. The optional REST explorer is provided by the separate `siecs_rest`
Bake package and must be imported explicitly.

## Components

```c
ECS_COMPONENT_DECLARE(Name, { /* fields */ });
ECS_COMPONENT_DEFINE(Name);
ECS_COMPONENT_REGISTER(Name);
```

Built-in components declared by the public API:

```c
ECS_RELATION_DECLARE(ChildOf);
ECS_COMPONENT_DECLARE(Name, { char *value; });
ECS_TAG_DECLARE(Disabled);
ECS_TAG_DECLARE(Abstract);
```

`Disabled` excludes an entity from queries by default. A query can match
disabled entities by mentioning `Disabled` explicitly, for example with
`ecs_filter(Disabled)`.

`Abstract` marks an entity as a prefab-like base that should not receive direct
component add, set, or remove operations from normal application code.


```c
typedef struct {
```

## Entities

```c
ecs_entity_t ecs_new(void);
ecs_entity_t ecs_new_no_reuse(void);
const char *ecs_entity_name(ecs_entity_t entity);
void ecs_defer_begin(void);
void ecs_defer_end(void);
bool ecs_is_alive(const ecs_entity_t entity);
bool ecs_is(ecs_entity_t entity, ecs_entity_t target);
void ecs_is_a(ecs_entity_t entity, ecs_entity_t target);
void ecs_kill(ecs_entity_t entity);
```

`ecs_new_no_reuse()` allocates a fresh, highest entity index instead of taking
an index from the free-list. Use it when numeric entity ordering must follow
allocation order; the tradeoff is that freed indices remain unused by this
allocator.

`ecs_is_a()` creates an inheritance link from `entity` to `target`.
`ecs_is()` checks whether an entity is or inherits from `target`.

## Component Access

Typed helpers:

```c
ecs_add(entity, Component);
ecs_remove(entity, Component);
ecs_has(entity, Component);
ecs_get(entity, Component);
ecs_try_get(entity, Component);
ecs_set(entity, Component, { /* value */ });
```

Id-based functions:

```c
void ecs_add_cid(ecs_entity_t entity, ecs_component_t id);
void ecs_remove_cid(ecs_entity_t entity, ecs_component_t id);
bool ecs_has_cid(const ecs_entity_t entity, ecs_component_t id);
bool ecs_has_cid_owned(const ecs_entity_t entity, ecs_component_t id);
void *ecs_get_cid(ecs_entity_t entity, ecs_component_t id);
void *ecs_try_get_cid(ecs_entity_t entity, ecs_component_t cid);
void ecs_set_cid(ecs_entity_t entity, ecs_component_t id, const void *data);
void ecs_move_cid(ecs_entity_t entity, ecs_component_t id, void *data);
```

`ecs_get()` and `ecs_get_cid()` assume the component exists. Use
`ecs_try_get()` or `ecs_try_get_cid()` when absence is valid.

```c
void ecs_with(ecs_component_t component, ecs_component_t require);
```

`ecs_with(component, require)` declares that adding `component` also adds
`require` first.

Requirement cycles are invalid and are asserted in debug builds when declared.

## Resources

Resources are typed values stored once per world. They use `ecs_resource_t`
ids, separate from component ids.

```c
ECS_RESOURCE_DECLARE(Time, { float dt; });
ECS_RESOURCE_DEFINE(Time);
ECS_RESOURCE_REGISTER(Time);
ECS_RESOURCE(Time, { float dt; });
```

Typed helpers:

```c
ecs_set_resource(Time, { .dt = 0.016f });
ecs_get_resource(Time);
ecs_get_resource_read(Time);
ecs_try_get_resource(Time);
ecs_try_get_resource_read(Time);
ecs_has_resource(Time);
ecs_remove_resource(Time);
```

Id-based functions:

```c
typedef struct {
    const char *name;
    uint64_t size;
    ecs_type_ops_t ops;
    ecs_resource_hook_t on_set;
    ecs_resource_hook_t on_remove;
} ecs_resource_desc_t;

ecs_resource_t ecs_resource_register(ecs_resource_t *id, const ecs_resource_desc_t *desc);
ecs_resource_t ecs_resource_init(const ecs_resource_desc_t *desc);
ecs_resource_t ecs_resource_find(const char *name);
bool ecs_resource_is_registered_rid(ecs_resource_t id);
void ecs_set_resource_rid(ecs_resource_t id, const void *data);
void ecs_move_resource_rid(ecs_resource_t id, void *data);
void *ecs_resource_rid(ecs_resource_t id);
void *ecs_try_resource_rid(ecs_resource_t id);
bool ecs_has_resource_rid(const ecs_resource_t id);
void ecs_remove_resource_rid(ecs_resource_t id);
```

`ecs_resource_rid()` asserts if the resource is absent. Use
`ecs_try_resource_rid()` when absence is valid. Resource `on_set` hooks run when
a resource is set, and `on_remove` hooks run when a resource is removed or when
the world is destroyed.

## Queries

```c
#define ecs_query(...)
ecs_query_id_t ecs_query_init(const ecs_query_desc_t *query);
void ecs_query_fini(ecs_query_id_t qid);
uint32_t ecs_query_count(ecs_query_id_t qid);

#define ecs_query_each(it, i, ...)
#define ecs_query_entities(entity, ...)
```

```c
typedef enum {
    EcsIn,
    EcsOut,
    EcsInOut,
    EcsInOptional,
    EcsInOutOptional,
    EcsFilter,
    EcsNot,
    EcsInUp,
    EcsInUpOptional,
} ecs_term_access_t;

typedef struct {
    ecs_component_t id;
    uint32_t access;
} ecs_query_term_t;

typedef struct {
    ecs_query_term_t terms[ECS_QUERY_TERM_CAPACITY];
    ecs_query_relation_term_t relations[ECS_QUERY_RELATION_CAPACITY];
    ecs_query_order_t order_by;
    ecs_entity_t is_a;
} ecs_query_desc_t;
```

```c
typedef enum {
    EcsRelationRequired,
    EcsRelationOptional,
    EcsRelationExcluded,
    EcsRelationTarget,
    EcsRelationDepth,
} ecs_query_relation_kind_t;

typedef struct {
    ecs_entity_t target;
    ecs_relation_id_t id;
    ecs_query_relation_kind_t kind;
} ecs_query_relation_term_t;

typedef int (*ecs_query_order_func_t)(const ecs_table_t *a,
                                      const ecs_table_t *b,
                                      uint64_t data);

typedef struct {
    ecs_query_order_func_t func;
    uint64_t data;
} ecs_query_order_t;
```

An order callback returns a negative value when table `a` precedes table `b`,
zero when they have equal order, and a positive value otherwise. It must be
pure because it runs while the query cache is built or updated:

```c
ecs_order_by_target(Relation);
ecs_order_by_depth(Relation);
```

Custom callbacks may inspect the matching relation target with
`ecs_table_target_id()` and table composition with `ecs_table_has_id()`.

`is_a` restricts the query to entities that inherit from the given target. The
match is transitive through the inheritance chain. Relation terms filter table
matching and do not create component fields.

```c
ecs_in(Component);
ecs_out(Component);
ecs_inout(Component);
ecs_in_optional(Component);
ecs_inout_optional(Component);
ecs_filter(Component);
ecs_not(Component);
ecs_up(Component, Relation);
ecs_up_optional(Component, Relation);
ecs_rel(Relation);
ecs_rel_opt(Relation);
ecs_not_rel(Relation);
ecs_to(Relation, target);
ecs_depth(Relation, depth);
ecs_order_by_target(Relation);
ecs_order_by_depth(Relation);
```

`ecs_field()` returns `EcsIn`, `EcsOut`, `EcsInOut`, `EcsInOptional`, and
`EcsInOutOptional` terms in declaration order. Optional fields return `NULL`
for batches whose table does not contain the component.

Queries implicitly add `ecs_not(Disabled)` unless their descriptor already
contains a term for `Disabled`. The implicit term is used by plain queries,
systems, and observers.

```c
ecs_iter_t ecs_query_iter(ecs_query_id_t query_id);
bool ecs_iter_next(ecs_iter_t *it);
typedef enum {
    EcsFieldNone,
    EcsFieldOwned,
    EcsFieldShared,
} ecs_field_kind_t;
ecs_field_kind_t ecs_field_kind(const ecs_iter_t *it, uint16_t field_index);
void *ecs_field(ecs_iter_t *it, uint16_t field_index);
bool ecs_field_is_shared(ecs_iter_t *it, uint16_t field_index);
```

`ecs_field_kind()` distinguishes owned, shared, and absent optional fields.

`ecs_target_at()` returns a relation target for one row of the current batch.
`ecs_targets()` returns contiguous `ecs_relation_target_t` records for `Dense`
and `ByDepth` relations. `ecs_to()` is valid for `ByTarget` relations, while `ecs_depth()`
`ecs_order_by_target()` is valid for `ByTarget` relations, while
`ecs_depth()` and `ecs_order_by_depth()` are valid for `ByDepth` relations.

## Systems

```c
typedef enum {
    EcsPreStart,
    EcsStart,
    EcsPostStart,
    EcsOnLoad,
    EcsPostLoad,
    EcsPreUpdate,
    EcsOnUpdate,
    EcsPostUpdate,
    EcsPreRender,
    EcsOnRender,
    EcsPostRender,
    EcsPhaseCount,
} ecs_phase_t;
```

`ecs_progress()` runs enabled systems in phase order. `EcsPreStart`,
`EcsStart`, and `EcsPostStart` are run only by the first `ecs_progress()` call
for a world. Manual `ecs_run_phase()` calls still run any valid phase normally.
`OnPreUpdate`, `OnUpdate`, `OnPostUpdate`, and `OnRender` are compatibility
aliases for the matching `Ecs*` names.

```c
typedef struct {
    const char *name;
    ecs_query_desc_t query;
    void (*callback)(ecs_iter_t *);
    uintptr_t user_data;
    void (*user_data_dtor)(uintptr_t user_data);
    ecs_phase_t phase;
    ecs_system_id_t after[ECS_SYSTEM_AFTER_CAPACITY];
    bool disabled;
} ecs_system_desc_t;
```

```c
#define ecs_system(...)
ecs_system_id_t ecs_system_init(const ecs_system_desc_t *desc);
bool ecs_progress(void);
void ecs_run(void);
void ecs_run_phase(ecs_phase_t phase);
void ecs_run_system(ecs_system_id_t system);
void ecs_system_enable(ecs_system_id_t system);
void ecs_system_disable(ecs_system_id_t system);
```

`after` declares systems that must run first in the same phase. It accepts up to
`ECS_SYSTEM_AFTER_CAPACITY` system ids. System id `0` is reserved, so an empty
`after` array is written as `{ 0 }` or omitted. Dependency cycles and
cross-phase dependencies are debug assertion failures.

Example:

```c
static void Move(ecs_iter_t *it) {
    Position *p = ecs_field(it, 0);
    Velocity *v = ecs_field(it, 1);

    for (uint32_t i = 0; i < it->count; i++) {
        p[i].x += v[i].x;
        p[i].y += v[i].y;
    }
}

ecs_system({
    .name = "Move",
    .phase = EcsOnUpdate,
    .query = { .terms = { ecs_inout(Position), ecs_in(Velocity) } },
    .callback = Move,
});

ecs_progress();
```

## C++ API

The C++ API is a header-only typed wrapper over the C runtime. Include
`<siecs.h>` for the complete facade, or include a header from
`<siecs/cpp/>` when only one public wrapper is needed. The built-in C component
types such as `Disabled`, `Abstract`, `Name`, and `ChildOf` remain in the global
namespace.

### World

```cpp
ecs::init();
ecs::progress();
ecs::run();
ecs::run_phase(EcsOnUpdate);
ecs::quit();
ecs::fini();
```

Initialize with optional features when needed:

```cpp
ecs::init({ .target_fps = 60 });
ecs::fini();
```

`ecs::init()` and `ecs::fini()` manage the process-wide world. The wrapper does
not provide an RAII world object, so applications must call `ecs::fini()` when
the world is no longer needed.

### Components and entities

```cpp
#include <cassert>

struct Position { float x, y; };

auto entity = ecs::entity::create()
    .set(Position{ .x = 1.0f, .y = 2.0f });

auto &position = entity.get<Position>();
position.x += 1.0f;
entity.add<Disabled>();
entity.remove<Disabled>();
assert(entity.has<Position>());
if (auto *nullable = entity.try_get<Position>()) {
    nullable->y += 1.0f;
}
auto id = entity.id();
assert(ecs::entity::from(id).is_alive());
assert(!ecs::entity::null().is_alive());
auto named = ecs::entity::create("player");
named.kill();
```

Typed components are registered automatically on first use. The entity API also
provides `kill()`, `is_alive()`, `is(entity)`, `enable()`, `disable()`,
`is_enabled()`, and `is_disabled()`.

Use `ecs::component<T>()` when a C API descriptor needs the typed component id.

Typed entities create one stable entity for a C++ type and optionally assign a
name:

```cpp
struct Player {};
auto player = ecs::entity::create<Player>("player");
auto player_type = ecs::entity::typed<Player>();
```

Inheritance uses `abstract()`, `is_a(...)`, and `is_a<T>()`:

```cpp
auto prototype = ecs::entity::create().set(Position{ 0.0f, 0.0f }).abstract();
auto instance = ecs::entity::create().is_a(prototype);
auto another = ecs::instantiate(prototype);
```

`child_of(parent)` assigns the built-in `ChildOf` relation. Register custom
relation types with `ecs::relation<T>(desc)`. Use `relate<T>()`, `unrelate<T>()`,
`has_relation<T>()`, and `target<T>()` to mutate and inspect them.

### Queries

```cpp
ecs::query()
    .require<Position>()
    .exclude<Disabled>()
    .each([](ecs::entity current, Position &position) {
        position.x += static_cast<float>(current.id() != 0);
    });

auto first = ecs::query().require<Position>().first();
```

The builder also provides `optional<T>()`, `is_a(target)`, `build()`, and
`build_handle()`. Relation filters use `with_relation<T>()`, `to<T>(target)`,
and `depth<T>(value)`. Table ordering uses `order_by_target<T>()`,
`order_by_depth<T>()`, or `order_by(...)`. Inherited fields use `up<Component,
Relation>()`. A
callback can receive `ecs::entity` as its first argument. `each()` and `first()`
are one-shot operations; they create and destroy the underlying C query. A
`query_handle` owns a persistent query id and releases it automatically:

```cpp
ecs::query().require<Position>().each([](Position &position) {
    position.x += 1.0f;
});
```

Optional callback fields use `ecs::optional<T>`. The value converts to `false`
when the component is absent for the current table and supports `get()`,
`operator->`, and `operator*` when present.

### Systems

```cpp
auto move = ecs::system("Move")
    .require<Position>()
    .phase(EcsOnUpdate)
    .each([](Position &position) {
        position.x += 1.0f;
    });
```

`ecs::system` supports `require<T...>()`, `optional<T...>()`, `exclude<T...>()`,
`phase()`, `after()`, `disabled()`, and `each()`. Callback component terms are
inferred from their parameter types. Resource parameters do not become query
terms:

```cpp
ecs::system("Move").each([](ecs::res<const Time> time, Position &position) {
    position.x += time->dt;
});
```

System ids can be controlled through the C++ helpers:

```cpp
ecs::disable_system(move);
ecs::enable_system(move);
ecs::run_system(move);
```

### Resources

```cpp
ecs::set_resource(Time{ .dt = 0.016f });
auto time = ecs::resource_handle<Time>();
time.get().dt += 0.001f;
if (auto *maybe_time = time.try_get()) {
    maybe_time->dt += 0.001f;
}
bool exists = time.has();
time.remove();
```

`ecs::res<T>` is the callback and observer view type. It supports `operator->`,
`operator*`, and `get()`. `ecs::resource_handle<T>` provides typed `set()`,
`get()`, `try_get()`, `has()`, and `remove()` operations.

### Observers and events

Built-in events use `ecs::OnAdd`, `ecs::OnRemove`, `ecs::OnSet`,
`ecs::OnRelationSet`, and `ecs::OnRelationRemove`. Custom events are represented
by an empty C++ type:

```cpp
struct Damaged {};

ecs::observe<Damaged>().each([](Health &health) {
    health.value -= 1;
});

ecs::trigger<Damaged>(entity);
```

`ecs::event<T>()` returns the custom event id associated with `T`; `observe<T>()`
and `trigger<T>()` use that id automatically.

Observer callbacks must be stateless. Component observers normally receive at
least one component argument. Relation observers may receive only
`ecs::observer_event` and use `with_relation<T>()` to filter the relation type:

```cpp
auto changed = ecs::observe<ecs::OnRelationSet>();
changed.with_relation<GroupOf>();
changed.each([](ecs::observer_event event) {
    auto *change = event.trigger_data<ecs_relation_event_t>();
    log_relation(change->old_target, change->new_target);
});
```

Callbacks may also receive `ecs::entity` first and `ecs::res<T>` resource
arguments. Add `ecs::observer_event` as the first callback argument to access
`target()`, `id()`, `user_data()`, and typed `trigger_data<T>()`.

### Modules

```cpp
#include <cassert>

struct Physics {
    float gravity;

    void import() {
        ecs::system("Move").each([](Position &position) {
            position.x += 1.0f;
        });
    }
};

auto physics = ecs::import<Physics>(9.81f);
auto same_module = ecs::module<Physics>();
physics.disable();
same_module.enable();
assert(same_module.is_enabled());
```

`module_ref<T>` also provides `id()` and an explicit boolean conversion. Module
imports are idempotent in the active world; the first properties value wins.

### C++ Reflection

Plain C++ component structs are stored and queried, but their REST schema has no
fields by default. Add the `reflected(...)` declaration when a component must
be serialized or exposed through the REST explorer:

```cpp
struct Position {
    reflected(float x; float y;);
};
```
